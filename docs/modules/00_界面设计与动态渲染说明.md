## 1. 先说意义：我们为什么要做这个界面？

想象真实场景：医生手里有一张**纸质健康档案表**，填完锁进柜子——十年后想查"去年有个哮喘的患儿"，只能一页页翻。

我们这个项目做的事情是：**把这张纸质表搬进电脑，再把电脑里的档案变成 DNA 序列长期保存**。整条流水线是：

```
医生在界面上点选填写  →  存入数据库  →  编码成 DNA 序列  →  需要时解码读回
     （前端）              （数据库）        （编解码模块）         （编解码模块）
```

所以前端的身份是**整条流水线的入口**，它的意义就三条：

1. **让不会用电脑的人也能录档案**——界面上没有一个需要"打字"的医学栏位，全部是点选，像做选择题一样填完一份病历；
2. **把纸质表的栏目变成数据**——医生勾选的每一项，都被翻译成数据库里的一行记录，从此可查、可统计、可归档；
3. **保证喂给 DNA 编码的内容是干净的**——界面只允许从标准字典里选（不自由发挥），编码时就不会出现"高血压"和"高血压病"两种写法导致解码对不上的问题。

一句话总结：**界面是"人的语言"和"机器的语言"之间的翻译官。**

## 2. 最终效果：界面就长手绘稿那个样子（已定稿）

界面定稿 = 你见过的那张**手绘表格**，2026-11-17 拍板，不再改。文字版布局如下：

```
┌─────────────────────────────────────────────────────────────┐
│  姓名：____  性别：[▼]  民族：[▼]  身份证号：____              │
│  档案编号：系统自动生成        建档日期：自动填今天              │   ← ①封面行（6 栏）
├─────────────────────────────────────────────────────────────┤
│  一、既往史与家族史                                            │
│    既往患病史：[点选多选]   手术史：[点选多选]                  │
│    外伤史：[点选多选]      家族史：[点选多选]                  │   ← ②
│    高危因素：[点选多选]                                        │
├─────────────────────────────────────────────────────────────┤
│  二、过敏史                                                    │
│    过敏原：[点选多选]  过敏反应：[点选多选]  药物过敏史：[点选]  │   ← ③
├─────────────────────────────────────────────────────────────┤
│  三、个人生活史                                                │
│    吸烟史：[单选]  饮酒史：[单选]                              │   ← ④
│    饮食情况：[点选]    作息情况：[点选]                        │
├─────────────────────────────────────────────────────────────┤
│  四、疾病分类：[点选多选]（选项 = 国家疾病分类 22 章）           │   ← ⑤
├─────────────────────────────────────────────────────────────┤
│  五、症状表现：[点选多选]     伴随症状：[点选多选]               │   ← ⑥
├─────────────────────────────────────────────────────────────┤
│  六、体格检查异常：[点选多选]                                  │   ← ⑦
├─────────────────────────────────────────────────────────────┤
│           [ 保存档案 ]      [ 编码归档 ]                       │   ← ⑧底部按钮
└─────────────────────────────────────────────────────────────┘
```

三个设计要点，每一处都有原因：

**要点 1：封面行是"身份"，其余是"健康"。** 姓名、身份证号这种每个人都不一样的信息，存数据库的封面表（`archive_records`）；下面 16 个空才是健康内容。注意封面行也不是全打字——性别、民族是下拉框。

**要点 2：中间 16 个空，全部是点选（枚举）。** 这是项目最硬的一条规矩："能填的必须是枚举"。每个空旁边都有一个候选项清单，医生只能从清单里勾，不能自己造词。候选项从哪来？全部来自国家标准字典：

| 空的个数 | 候选项来源 | 用途 |
|---:|---|---|
| 9 个空 | ICD-10（35,867 条国家疾病字典，含派生、复用与混合） | 国家给每种疾病、症状、损伤、药物过敏都编了号 |
| 1 个空（手术史） | ICD-9-CM3 3.0（14,518 条手术码） | 国家给每种手术也编了号 |
| 3 个空 | WS/T 364.5 卫生行业标准值域 | 高危因素、吸烟、饮酒的官方选项 |
| 3 个空 | 自建院内字典（过敏原、饮食、作息） | 国家没有标准的，我们自己定一份 |

逐空对账：既往患病史、外伤史、家族史、疾病分类、症状表现、伴随症状、体格检查异常、过敏反应、药物过敏史这 9 个空都落到 ICD-10（其中药物过敏史用 Z88 章、疾病分类用 22 章派生，过敏反应和症状体征是"码表为主 + 自建补常见项"的混合）；手术史单独用手术码表；高危因素、吸烟史、饮酒史用 WS/T；过敏原、饮食、作息自建。与数据库最终版 §4.2/§8 逐条一致。

**要点 3：手绘稿上没有的栏目（出生史、随访记录、生命体征等），这次不做。** 不是丢了，是 2026-11-17 明确"最终呈现以手绘稿为准"，那些栏目不入库、不上界面。依据和逐项对账见 `02_数据库_开发书/08_设计对账表_v4.0.md`。

## 3. 为什么这样设计界面最省事：界面是"长"出来的，不是"画"出来的

这是整个项目最关键的一处，也是实现时最容易偏离的一处。

**静态写死的做法**：在代码里把 16 个空一个个手工写出来，每个空写死它的选项。问题是——以后想给"过敏原"加一项"芒果"，就得改代码、重新发版。

**我们的办法**：界面不写死任何栏目和选项，而是**启动时去数据库问三张表**：

```
sections 表（8 行）：  "界面分几个区块？"      → 封面行 + 六个区块
fields  表（16 行）：  "每个区块里有几个空？"  → 每个空的名称、必填与否
options 表：           "每个空能勾哪些项？"    → 候选项清单
```

界面照着这三张表自动搭出来。以后要加一个候选项、改一个名称，**改的是数据库里的几行数据，不是代码**。这就是《数据库结构与数据流说明》里说的"连表头都进了数据库"——表头进库，就是为了界面能自动生成。

落地要求只有一条：**表单渲染必须动态（读表生成），禁止把 16 个空写死在代码里。**

## 4. 一次完整的使用旅程（数据怎么流）

**场景：医生给小明建档案。**

| 步骤 | 界面上发生什么 | 数据库里发生什么 |
|---:|---|---|
| 1 新建档案 | 点"新建"，填姓名/身份证号 | 封面表多一行，档案编号自动生成 |
| 2 填健康内容 | 在 16 个空里点选，比如既往患病史勾"高血压、哮喘" | 每勾一项，`answers` 表多**一行**（一个勾占一行，两个勾就是两行） |
| 3 保存 | 点"保存档案" | 数据落库，以后随时能打开重新看 |
| 4 编码归档 | 点"编码归档" | 整份档案的勾选结果被编码成 ATCG 字符串存进 `dna_sequences`，同时留一份解码记录 |

有个细节值得知道：因为"一个勾占一行"，以后想统计"建档的 500 个孩子里有多少个有哮喘"，一条查询就能算出来——这就是当初坚持全部点选、不让人打字的第二个回报。

## 6. 三句话总结 + 术语对照

**三句话总结：**
1. 界面就是把手绘表搬进电脑：6 栏封面 + 6 个区块 16 个空，全部点选，没有打字的医学栏位。
2. 界面不是画死的，是从数据库三张表"长"出来的——改选项 = 改数据，不改代码。
3. 前端模块待办：去掉登录、表单动态渲染、保存走 answers，其余（文件上传、AI 识别）已经能跑。

**术语对照（每个一句话）：**

| 词 | 意思 | 我们项目里的例子 |
|---|---|---|
| 前端 / 界面层 | 用户看得见、点得着的部分 | `ui_interface.py` |
| Flet | 用 Python 写桌面窗口程序的工具库 | 整个界面都是它画的 |
| 枚举 / 点选 | 只能从固定清单里选，不能自由输入 | 16 个空全部如此 |
| 动态渲染 | 界面内容在运行时读数据生成，不写死 | 表单读 sections/fields/options |
| 归档 | 把整理好的数据长期保存 | 点"编码归档"变成 DNA 序列 |
