## 1. 引言

### 1.1 项目背景

医疗健康档案包含大量敏感个人信息，传统电子存储方式面临数据泄露、长期保存成本高、格式淘汰等风险。本项目将医疗数据编码为 **DNA序列** 进行存储，利用 DNA 分子的高密度存储特性（1克DNA可存储约215PB数据）和超长保质期（理论上可达数百年），实现医疗数据的**安全加密**与**长期冷归档**。

### 1.2 项目目标

| 目标编号 | 目标描述 | 优先级 |
|---------|---------|--------|
| G-01 | 支持医疗文档的智能识别与结构化提取 | P0 |
| G-02 | 实现文本→二进制→DNA序列的完整编码流程 | P0 |
| G-03 | 实现DNA序列→二进制→文本的完整解码流程 | P0 |
| G-04 | 编码结果满足DNA生物特性约束（GC含量、热稳定性） | P0 |
| G-05 | 解密时支持基于数据库的智能纠错 | P1 |
| G-06 | 支持多任务并行，UI不阻塞 | P1 |
| G-07 | 提供友好的图形用户界面 | P1 |
| G-08 | 数据本地存储，保护隐私 | P0 |

### 1.3 文档范围

本文档从软件设计说明书(SDD)反向提取需求，不新增任何功能。涵盖：用户角色定义、功能需求、性能约束、安全要求。

## 3. 功能需求

### 3.1 加密功能（数据写入）

#### FR-E01：多源数据输入

| 输入方式 | 说明 | 优先级 |
|---------|------|--------|
| 手动填写表单 | 在线填写33个字段的健康档案信息 | P0 |
| 导入文档 | 上传 .txt / .docx / .pdf 文档，自动解析文本 | P0 |
| 上传图片 | 上传图片文件（预留OCR接口） | P2 |

#### FR-E02：AI智能字段提取

| 能力 | 说明 | 优先级 |
|------|------|--------|
| 文档解析 | 从上传文档中提取纯文本内容 | P0 |
| 字段识别 | AI自动识别并结构化33个目标字段 | P0 |
| 进度反馈 | 流式返回处理进度，实时更新UI | P0 |
| 结果预览 | 提取结果填充到表单，支持人工修正 | P0 |

**AI输出格式**：
```json
{
  "物理存储": {"姓名": "张三", "性别": "男", ...},
  "反复存储": [{"随访日期": "2026-10-01", ...}],
  "病症记录": {"苯丙酮尿症": "阴性", ...}
}
```

#### FR-E03：数据预处理

| 处理步骤 | 说明 | 优先级 |
|---------|------|--------|
| 字段分类 | 将数据分为物理存储(23字段)、反复存储(3字段)、病症记录(7字段) | P0 |
| 拼音转换 | 反复存储字段中文→拼音（C++编码器只接受英文） | P0 |
| 病症标准化 | 中文病症名→英文映射（查236条病典） | P0 |
| 密钥生成 | 基于患者姓名+出生日期生成16字符加密密钥 | P0 |

#### FR-E04：DNA编码

| 步骤 | 说明 | 优先级 |
|------|------|--------|
| 文本转二进制 | 英文文本 → ASCII → 二进制串 | P0 |
| XOR加密 | 明文二进制 ⊕ 密钥二进制 = 密文二进制 | P0 |
| 二进制转DNA | 11→A, 01→T, 10→C, 00→G 映射 | P0 |
| 生物特性优化 | GC含量校验(40%-60%)、热稳定性校验、自适应修复 | P0 |
| 输出结果 | DNA序列 + GC含量 + 热稳定性系数 + 序列长度 | P0 |

#### FR-E05：数据存储

| 存储内容 | 存储位置 | 优先级 |
|---------|---------|--------|
| 原始档案记录 | SQLite archive_records 表 | P0 |
| DNA编码结果 | SQLite dna_sequences 表（含密钥哈希） | P0 |
| 上传文件副本 | data/uploads/ 目录 | P0 |

### 3.2 解密功能（数据读取）

#### FR-D01：多源DNA输入

| 输入方式 | 说明 | 优先级 |
|---------|------|--------|
| 手动粘贴 | 用户直接在文本框输入DNA序列字符串 | P0 |
| 导入文件 | 读取包含DNA序列的文本文件 | P0 |
| 数据库选择 | 从已存储的DNA序列列表中选择 | P0 |

#### FR-D02：DNA解码

| 步骤 | 说明 | 优先级 |
|------|------|--------|
| 序列校验 | 验证DNA序列合法性（仅含A/T/C/G/X/Y字符） | P0 |
| 移除人工碱基 | 剔除X/Y标记的填充区域 | P0 |
| DNA转二进制 | A→11, T→01, C→10, G→00 反向映射 | P0 |
| XOR解密 | 密文二进制 ⊕ 密钥二进制 = 明文二进制 | P0 |
| 二进制转文本 | ASCII 还原为原始英文文本 | P0 |

#### FR-D03：智能纠错

| 步骤 | 说明 | 优先级 |
|------|------|--------|
| 相似度检索 | 在数据库中查找相似档案记录作为参考 | P1 |
| 损坏程度分析 | 计算位翻转率、缺失率，评估损坏等级 | P1 |
| AI纠错推理 | 结合参考文本，AI推断并修复错误字符 | P1 |
| 纠错报告 | 输出修正详情、置信度、错误率 | P1 |

#### FR-D04：结果展示与导出

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 结果展示 | 还原的结构化档案数据展示在界面上 | P0 |
| JSON导出 | 导出为JSON格式文件 | P0 |
| DOCX导出 | 导出为Word文档（使用模板） | P1 |
| 纠错日志 | 显示数据完整性报告和纠错详情 | P1 |

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 | 测试方法 |
|------|------|---------|
| AI字段提取响应时间 | < 30秒 | 使用标准测试文档计时 |
| DNA编解码响应时间 | < 5秒 | 使用标准输入计时 |
| UI界面响应时间 | < 100ms | 操作到视觉反馈 |
| 并发任务数 | ≥ 3个 | 同时启动多个任务 |
| 数据库查询响应 | < 500ms | 万条记录级别查询 |

### 4.2 安全需求

| 需求 | 实现方式 | 优先级 |
|------|---------|--------|
| 密钥安全 | 存储SHA-256哈希，不存明文 | P0 |
| 数据隐私 | 本地SQLite存储，数据不上云 | P0 |
| AI隐私 | Ollama本地部署，数据不出本机 | P0 |
| 临时文件安全 | 程序退出时自动清理 | P1 |
| 软删除 | 档案记录不物理删除，仅标记 | P1 |

### 4.3 兼容性需求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 / Windows 11 |
| Python版本 | >= 3.8 |
| 屏幕分辨率 | 最低 1280×720 |
| 内存要求 | ≥ 4GB RAM |
| 磁盘空间 | ≥ 1GB 可用空间 |

### 4.4 可用性需求

| 需求 | 说明 |
|------|------|
| 错误提示 | 所有异常情况显示友好的中文提示 |

### 5.3 按用户场景划分

#### 场景1：完整的加密流程

```
用户打开系统 → 游客登录 → 选择"加密" → 
  ├─ 方式A: 手动填写33个字段
  ├─ 方式B: 上传文档 → AI自动提取字段 → 人工修正
  └─ 方式C: 上传图片（预留OCR）
→ 确认数据 → 系统自动生成密钥 → 执行DNA编码 → 
→ 显示编码结果（DNA序列/GC含量/热稳定性） → 保存到数据库
```

#### 场景2：完整的解密流程

```
用户打开系统 → 选择"解密" → 
  ├─ 方式A: 粘贴DNA序列
  ├─ 方式B: 导入包含DNA的文件
  └─ 方式C: 从数据库选择已存储的序列
→ 输入解密密钥 → 执行DNA解码 → 
→ （可选）智能纠错 → 显示还原的档案数据 → 
→ 导出为JSON或DOCX
```

## 6. 约束条件

### 6.1 技术约束

| 约束 | 说明 |
|------|------|
| Python版本 | >= 3.8 |
| GUI框架 | Flet >= 0.21.0 |
| 数据库 | SQLite 3.x（无需额外安装服务） |
| AI引擎 | Ollama + Qwen2.5（本地部署） |
| C++编译器 | C++17 标准 |
| 操作系统 | Windows 10/11 |

### 6.2 数据约束

| 约束 | 说明 |
|------|------|
| 病典词条数 | 236条预设（8大分类） |
| 物理存储字段 | 23个固定字段 |
| 病症记录字段 | 7个字段 |
| 反复存储字段 | 3个字段（支持多条） |
| 总字段数 | 33个 |
| DNA合法字符 | A, T, C, G, X, Y |
| GC含量目标范围 | 40% - 60%（理想50%） |
| 密钥长度 | 16字符（十六进制） |
| 密钥存储 | 仅存SHA-256哈希 |

### 6.3 业务约束

| 约束 | 说明 |
|------|------|
| 游客模式 | 当前版本不支持账号注册登录 |
| 本地存储 | 所有数据仅存本地，不上传云端 |
| AI依赖 | AI功能需要Ollama服务运行 |
| C++依赖 | 编解码需要编译后的exe文件 |
| 单机应用 | 不支持多用户同时操作同一数据 |

## 7. 术语表

| 术语 | 全称/解释 |
|------|----------|
| DNA编码 | 二进制→DNA碱基(A/T/C/G)的映射过程 |
| DNA解码 | DNA碱基→二进制→文本的反向过程 |
| GC含量 | DNA序列中G和C碱基所占比例，影响双链稳定性 |
| 热稳定性 | DNA分子的耐热能力，与GC含量正相关 |
| 人工碱基 | X/Y标记，用于标识编码时的填充/修复区域 |
| XOR加密 | 异或加密算法，明文⊕密钥=密文，密文⊕密钥=明文 |
| 冷归档 | 长期低频访问的数据存储方式 |
| 病典 | 病症词典，中英文病症名称映射表（236条） |
| 物理存储 | 档案中固定不变的信息（23个字段） |
| 反复存储 | 档案中动态变化的信息（随访记录等，3个字段） |
| Ollama | 本地部署的大语言模型运行框架 |
| Qwen2.5 | 阿里通义千问大模型（本项目的AI引擎） |
| Flet | Python跨平台GUI框架（类似Flutter） |
