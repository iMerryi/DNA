## 一、这个项目是什么

基于 DNA 序列编码的医疗数据加密**桌面软件**：把医疗健康档案编码为 DNA 序列存储，实现安全加密与长期冷归档。
**Flet 原生窗口，单进程 `python main.py` 直接启动；不涉及浏览器、不起 Web 服务、不开端口。**

**加密流程**：医疗文档 → AI 智能提取字段 → 数据分类（物理/反复/病症）→ 密钥生成 → DNA 序列编码（XOR 加密 + 碱基映射 + GC 含量/热稳定性优化）

**解密流程**：DNA 序列输入 → 密钥验证 → 解码还原 → 智能纠错 → 档案导出（JSON/DOCX）

技术栈：Python 3.8+ / Flet 桌面 GUI / C++17（DNA 编解码核心算法）/ SQLite / 本地 Ollama（Qwen2.5:7B）

> 唯一的网络调用是 Python → 本机 Ollama `localhost:11434`（AI 字段提取，可选，不装则降级），与界面形态无关。

## 五、怎么把项目跑起来

> ⚠️ **当前可运行基线（先看这段再敲命令）**
> 这份包**还不是一个能完整跑通加解密的软件**。按下面第 4 步启动后：
> - `data_store.py` 仍是 v3.0 键值模型，启动时**自动创建一个旧结构的库**；它不是 v4.1。目标结构请看 `02_数据库_开发书/` 的建表脚本与样例库。（`ui_interface.py` 的 `PROJECT_ROOT` 路径 bug 已修正，库与封面图均按 `06_代码现状快照/` 为根定位。）
> - `dna_codec.py` / `error_corrector.py` 不存在，`main.py` 会静默注入 `None` → **界面能弹出，但加密/解密按钮点了没有反应且不报错**。
> - 首屏仍是已决定删除的登录/游客选择页。
>
> **看到窗口 ≠ 跑通。** 真正跑通的判据见第六节。
>
> Python 建议 **3.10 或 3.11**：`requirements.txt` 锁了 `flet==0.21.2`，在 3.13+ 上可能装不上或报 API 不兼容。

```bash
# 1. Python 依赖（版本已实测锁定）
pip install -r 06_代码现状快照/requirements.txt

# 2. 本地 AI（可选，不装也能启动，AI 功能降级）
ollama pull qwen2.5:7b-instruct

# 3. C++ 编解码器（两个源码均已可直接编译）
#    编译产物放哪、怎么被 dna_codec.py 找到，见 04_DNA编解码_核心算法/C++调用协议.md
g++ -std=c++17 -O2 DNA_encoder.cpp -o dna_encoder.exe
g++ -std=c++17 -O2 DNA_decoder.cpp -o dna_decoder.exe

# 4. 启动主程序（Flet 原生窗口，不需要浏览器）
python 06_代码现状快照/src/main.py
```

**注意**：flet 必须是 0.21.x，高版本 API 不兼容现有界面代码。

1. `python 02_数据库_开发书/07_验收脚本_verify_schema.py --db 02_数据库_开发书/medical_archive_v4_样例.db` 全绿（不带 `--db` 默认也是验这个样例库；自建库后把路径换成自己的库）。
2. 手动填一份儿童健康档案 → 加密 → 得到 DNA 序列 → 解密 → 导出 JSON 与原文一致。
   - 注意：`DNA_encoder.cpp` 用了 `srand(time(0))` + `rand()` 随机插入修复片段，**同一份档案两次编码得到的序列不同是正常现象**，不要当成 bug；验收只要求往返还原一致 + 字符集/GC/定界符合约束。
3. UI 全程不出现 `sqlite3` 直连与 users.json。
4. 断网状态下核心加密/解密流程仍可用（AI 只做增强，不是依赖）。
