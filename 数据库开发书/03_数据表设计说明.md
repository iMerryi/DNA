# 数据表设计说明

> 数据库：SQLite　|　文件：`data/db/medical_archive.db`　|　版本：v3.0（v2.1 + 账号模块）
> 每张表按「用途 → 字段 → 主键/外键 → 约束 → 索引」说明。

---

## 表1　`archive_records` 档案主表

**用途**：存放档案的身份标识与状态。只保留查询/排序必需的列，其余内容全部在键值表。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | **PK**，AUTOINCREMENT | 自增主键（内部） |
| record_id | TEXT | **NOT NULL，UNIQUE** | 业务号 `ARCHIVE_{YYYYMMDD}_{NNN}`，对外的唯一标识 |
| archive_number | TEXT | DEFAULT '' | 档案编号（用户填写） |
| name | TEXT | **NOT NULL** | 姓名 |
| gender | TEXT | DEFAULT ''，**CHECK 值域** | 性别规范值：male / female / unknown（空串表示未填） |
| nation | TEXT | DEFAULT '' | 民族 |
| id_number | TEXT | DEFAULT '' | 身份证号 |
| residence_address | TEXT | DEFAULT '' | 常住地址 |
| create_date | TEXT | DEFAULT '' | 建档日期（业务日期） |
| source | TEXT | DEFAULT 'manual'，**CHECK 值域** | 数据来源：manual / upload / ai |
| owner_id | INTEGER | FK，可 NULL | 归属用户 → `users.id`（v3.0 新增）；NULL = v1 迁移的历史数据 |
| created_at | TEXT | **NOT NULL** | 记录创建时间（系统写） |
| updated_at | TEXT | **NOT NULL** | 记录更新时间（系统写） |
| is_deleted | INTEGER | DEFAULT 0，**CHECK 0/1** | 软删除标记（1=已删，仅标记不物理删） |

- **主键**：`id`
- **唯一约束**：`record_id`
- **CHECK 约束**：`gender IN ('', 'male', 'female', 'unknown')`、`source IN ('manual', 'upload', 'ai')`、`is_deleted IN (0, 1)`
- **外键**：`owner_id → users(id)`（v3.0 起不再是无外键的根实体）
- **索引**：`idx_archive_name(name)`、`idx_archive_created(created_at)`、`idx_archive_deleted(is_deleted, created_at)`、`idx_archive_owner(owner_id)`
- **`record_id` 生成算法**：`ARCHIVE_` + 当日日期 + 当日 3 位序号；生成与插入必须同一事务，并发冲突时捕获 `IntegrityError` 重试（≤3 次）。

## 表2　`field_definitions` 字段字典

**用途**：全部业务字段的唯一登记处。前端表单渲染、AI 输出校验、写入合法性检查的唯一依据。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | **PK**，AUTOINCREMENT | |
| field_key | TEXT | **NOT NULL，UNIQUE** | 英文规范键，如 `allergy_source`；入库后不可改名 |
| section | TEXT | **NOT NULL** | 分组：identity / birth / history / allergy / lifestyle / reproductive / complaint / exam / followup |
| label_cn | TEXT | **NOT NULL** | 中文标签 |
| label_en | TEXT | **NOT NULL** | 英文标签 |
| value_type | TEXT | DEFAULT 'text'，**CHECK 值域** | text / date / number / enum / bool |
| is_multi | INTEGER | DEFAULT 0，**CHECK 0/1** | 1 = 多值字段（seq 从 1 递增） |
| is_active | INTEGER | DEFAULT 1，**CHECK 0/1** | 0 = 停用（前端不渲染，历史值可读） |
| unit_cn / unit_en | TEXT | DEFAULT '' | 单位，如 ℃ / °C |
| sort_order | INTEGER | DEFAULT 0 | 表单与导出顺序 |
| is_legacy | INTEGER | DEFAULT 0，**CHECK 0/1** | 1 = 从 v1 迁移而来 |

- **主键**：`id`；**唯一约束**：`field_key`
- **CHECK 约束**：`value_type IN ('text','date','number','enum','bool')`；`is_multi` / `is_active` / `is_legacy` 仅允许 0/1
- **外键**：无（被 `record_entries.field_key` 引用）
- **索引**：`idx_def_section(section, sort_order)`、`idx_def_active(is_active)`
- **种子数据**：60 条，由 `data/seed/seed_field_definitions.sql` 灌入，幂等。

## 表3　`record_entries` 内容键值表（核心）

**用途**：存放 53 个业务字段的具体取值。一条档案的内容 = 本表中 `record_id` 相同的一组行。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | **PK**，AUTOINCREMENT | |
| record_id | TEXT | **NOT NULL，FK①** | → `archive_records.record_id`，ON DELETE CASCADE |
| field_key | TEXT | **NOT NULL，FK②** | → `field_definitions.field_key` |
| seq | INTEGER | **NOT NULL**，DEFAULT 0，**CHECK ≥ 0** | 单值固定 0；多值从 1 连续递增 |
| value_cn | TEXT | DEFAULT '' | 中文值（界面展示） |
| value_en | TEXT | DEFAULT '' | 英文/规范值（编码交换）；开放文本与 value_cn 相同 |
| value_num | REAL | NULL | `value_type=number` 时的数值副本，供范围查询 |
| updated_at | TEXT | **NOT NULL** | 更新时间 |

- **主键**：`id`
- **外键**：①`record_id` → `archive_records(record_id)` CASCADE；②`field_key` → `field_definitions(field_key)`
- **唯一约束**：`UNIQUE(record_id, field_key, seq)` —— 不重不漏的槽位模型
- **`seq` 为 NOT NULL**：SQLite 的 UNIQUE 认为多个 NULL 互不冲突，若允许 NULL 会绕过「不重不漏」约束，因此数据库层强制非空
- **索引**：`idx_entries_record(record_id)`、`idx_entries_field(field_key)`、`idx_entries_num(field_key, value_num)`
- **特意的省略**：无 `is_deleted` 列（条目层不做软删除，见《06_数据安全说明》§4）；不为 `value_cn`/`value_en` 建索引——`LIKE '%kw%'` 前置通配符用不上 B-tree，建了只白占空间。

## 表4　`record_diseases` 病症结果表

**用途**：存放每条档案的病症筛查结果，词条由词典驱动。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | **PK**，AUTOINCREMENT | |
| record_id | TEXT | **NOT NULL，FK①** | → `archive_records.record_id`，CASCADE |
| disease_term_id | INTEGER | **NOT NULL，FK②** | → `disease_terms.id` |
| result_cn | TEXT | DEFAULT '' | 结果中文：阴性 / 阳性 / 未查 |
| result_en | TEXT | DEFAULT ''，**CHECK 值域** | 规范值：negative / positive / not_tested（空串表示未填） |
| seq | INTEGER | **NOT NULL**，DEFAULT 0，**CHECK ≥ 0** | 同一病症多次筛查的序号 |
| checked_at | TEXT | DEFAULT '' | 检查日期 |
| updated_at | TEXT | **NOT NULL** | 更新时间 |

- **唯一约束**：`UNIQUE(record_id, disease_term_id, seq)`
- **CHECK 约束**：`result_en IN ('', 'negative', 'positive', 'not_tested')`
- **索引**：`idx_disease_result(record_id, disease_term_id)`、`idx_disease_term(disease_term_id)`

---

## 表5　`disease_terms` 病症词典

**用途**：236 条标准病症词条，全局共享。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | **PK**，AUTOINCREMENT | |
| term_key | TEXT | **NOT NULL，UNIQUE** | **不可变**英文标识（如 `phenylketonuria`），DNA 载荷用这个 |
| chinese_name | TEXT | **NOT NULL，UNIQUE** | 中文名 |
| english_name | TEXT | **NOT NULL** | 英文展示名（可修改） |
| category | TEXT | DEFAULT 'general' | 分类（英文规范值） |
| is_active | INTEGER | DEFAULT 1，**CHECK 0/1** | 词条启停 |
| updated_at | TEXT | DEFAULT '' | 更新时间 |

- **双唯一约束**：`term_key`（稳定标识，永不改名）与 `chinese_name`（防重复词条）。
- **设计要点**：`english_name` 允许修词，不影响已编码的 DNA 载荷（载荷引用的是 `term_key`）。

---

## 表6　`dna_sequences` DNA 序列表

**用途**：DNA 编码结果。同一条档案可多次编码，历史版本置 `is_valid=0` 保留审计轨迹。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | **PK**，AUTOINCREMENT | |
| record_id | TEXT | **NOT NULL，FK** | → `archive_records.record_id` |
| dna_sequence | TEXT | **NOT NULL** | DNA 序列（ATCG） |
| key_hash | TEXT | **NOT NULL** | 密钥哈希（不存明文密钥） |
| cg_content | REAL | DEFAULT 0 | GC 含量 |
| thermal_stability | REAL | DEFAULT 0 | 热稳定性系数 |
| padded_zeros | INTEGER | DEFAULT 0 | 二进制补齐的 0 位数 |
| sequence_length | INTEGER | DEFAULT 0，**CHECK ≥ 0** | 序列长度 |
| original_text | TEXT | DEFAULT '' | 编码前明文（明文风险见《06_数据安全说明》§2.2） |
| encoded_at | TEXT | **NOT NULL** | 编码时间 |
| is_valid | INTEGER | DEFAULT 1，**CHECK 0/1** | 是否当前有效版本 |
| payload_version | TEXT | DEFAULT 'v2' | 编码载荷格式版本（可追溯） |
| payload_mode | TEXT | DEFAULT 'bilingual'，**CHECK 值域** | bilingual / canonical_en |

- **索引**：`idx_dna_record(record_id, is_valid)`、`idx_dna_sequence(dna_sequence)`
- **外键策略**：`record_id` 外键**不设 CASCADE**——物理删除档案会被外键拒绝，从而避免 DNA 审计链随档案一起丢失；需要销毁时按 05 §5 的依赖顺序显式清理。

## 表7　`decode_records` 解码记录表

**用途**：DNA 解码历史与 AI 纠错日志，与编码表构成完整审计链。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | **PK**，AUTOINCREMENT | |
| dna_record_id | INTEGER | **NOT NULL，FK** | → `dna_sequences.id` |
| decoded_text | TEXT | **NOT NULL** | 解码原文 |
| corrected_text | TEXT | DEFAULT '' | AI 纠错后文本 |
| confidence | REAL | DEFAULT 0，**CHECK 0–1** | 置信度 0.0–1.0 |
| error_rate | REAL | DEFAULT 0，**CHECK 0–1** | 错误率 0.0–1.0 |
| correction_log | TEXT | DEFAULT '{}' | 纠错日志（JSON） |
| decoded_at | TEXT | **NOT NULL** | 解码时间 |

- **CHECK 约束**：`confidence BETWEEN 0 AND 1`、`error_rate BETWEEN 0 AND 1`
- **索引**：`idx_decode_dna(dna_record_id)`

## 表9　`users` 用户表（v3.0 新增）

**用途**：单机账号，用于区分档案数据归属。不承担对抗性安全职责——密码哈希防"直接看到明文"，不防专业破解。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | **PK**，AUTOINCREMENT | |
| username | TEXT | **NOT NULL，UNIQUE** | 统一转小写存储判重（应用层负责，见下） |
| password_hash | TEXT | **NOT NULL** | 哈希（盐内嵌），**绝不存明文**；推荐 `pbkdf2$200000$salt$hash` 格式 |
| display_name | TEXT | DEFAULT '' | 界面显示昵称 |
| role | TEXT | DEFAULT 'user'，**CHECK 值域** | user / admin |
| is_active | INTEGER | DEFAULT 1，**CHECK 0/1** | 0 = 停用（数据保留，拒绝登录）；**不用物理删除**，保证归属外键可解析 |
| created_at | TEXT | **NOT NULL** | 注册时间 |
| last_login_at | TEXT | DEFAULT '' | 最后登录时间 |

- **CHECK 约束**：`role IN ('user','admin')`、`is_active IN (0,1)`
- **设计要点**：SQLite 的 UNIQUE 不区分大小写，`Tom` 与 `tom` 可同时入库——**应用层必须在写入前 `username.strip().lower()`**，这条在验收用例里（T12）。
- **索引**：`username` 唯一约束自动覆盖查询。

---

## 表10　`user_activity_log` 操作日志表（v3.0 新增）

**用途**：全操作审计链，记录登录、建档、编码、解码等关键动作，支撑"谁在什么时候对哪条档案做了什么"的追溯。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | **PK**，AUTOINCREMENT | |
| user_id | INTEGER | FK，可 NULL | 操作者 → `users.id`；NULL = 游客操作 |
| action | TEXT | **NOT NULL**，**CHECK 十枚举** | register / login / logout / create_record / update_record / delete_record / encode_dna / decode_dna / export_report / ai_extract |
| target_record_id | TEXT | DEFAULT '' | 目标档案号（无则空串） |
| detail | TEXT | DEFAULT '' | 补充信息（如失败原因） |
| created_at | TEXT | **NOT NULL** | 操作时间 |

- **写入策略**：日志写失败**不得阻断主流程**（接口内部吞异常）——但日志与业务使用同一连接 + WAL 模式，避免"另一连接被锁后日志被静默吞掉"。
- **只增不改**：无 UPDATE 入口，审计链不可篡改。
- **索引**：`idx_activity_user(user_id, created_at)`、`idx_activity_action(action, created_at)`

## 索引汇总

共 **16 个**显式索引（另有各表主键与 UNIQUE 自动索引；脚本中均为 `CREATE INDEX IF NOT EXISTS`，可重复执行）：

```sql
CREATE INDEX IF NOT EXISTS idx_archive_name        ON archive_records(name);
CREATE INDEX IF NOT EXISTS idx_archive_created     ON archive_records(created_at);
CREATE INDEX IF NOT EXISTS idx_archive_deleted     ON archive_records(is_deleted, created_at);
CREATE INDEX IF NOT EXISTS idx_archive_owner       ON archive_records(owner_id);
CREATE INDEX IF NOT EXISTS idx_entries_record      ON record_entries(record_id);
CREATE INDEX IF NOT EXISTS idx_entries_field       ON record_entries(field_key);
CREATE INDEX IF NOT EXISTS idx_entries_num         ON record_entries(field_key, value_num);
CREATE INDEX IF NOT EXISTS idx_def_section         ON field_definitions(section, sort_order);
CREATE INDEX IF NOT EXISTS idx_def_active          ON field_definitions(is_active);
CREATE INDEX IF NOT EXISTS idx_disease_result      ON record_diseases(record_id, disease_term_id);
CREATE INDEX IF NOT EXISTS idx_disease_term        ON record_diseases(disease_term_id);
CREATE INDEX IF NOT EXISTS idx_dna_record          ON dna_sequences(record_id, is_valid);
CREATE INDEX IF NOT EXISTS idx_dna_sequence        ON dna_sequences(dna_sequence);
CREATE INDEX IF NOT EXISTS idx_decode_dna          ON decode_records(dna_record_id);
CREATE INDEX IF NOT EXISTS idx_activity_user       ON user_activity_log(user_id, created_at);
CREATE INDEX IF NOT EXISTS idx_activity_action     ON user_activity_log(action, created_at);
```

**索引设计说明**：

1. 索引服务于确定的查询模式：列表排序（created_at）、分状态过滤（is_deleted 复合）、数值范围（value_num 复合）。
2. `idx_archive_name` 只对 `name = ?` 精确匹配与 `name LIKE '前缀%'` 生效；`list_records` 的关键词检索是 `LIKE '%kw%'`（前置通配符），**不能使用该索引**，会走全表扫描——这是千条级数据量下可接受的选择。
3. `idx_entries_record` 与 `idx_disease_result` 分别与两表 UNIQUE 约束的自动索引前缀重复，保留不影响正确性，仅增加少量写入开销。
4. **不建** `value_cn`/`value_en` 的内容索引：`LIKE '%关键词%'` 前置通配符无法使用 B-tree 索引；当前数据量（单机千条内）全表扫描在 10ms 量级。数据量超 1 万条再启用 FTS5 虚表方案（见设计文档附录 A），不提前优化。
