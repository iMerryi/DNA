## 3. 类型与取值规范

### 3.1 value_type 类型定义

| 类型 | 含义 | 存储要求 |
|---|---|---|
| text | 开放文本 | `value_cn` 存中文；`value_en` 与 `value_cn` 相同（开放文本不做翻译） |
| date | 日期 | 统一 `YYYY-MM-DD` 格式 |
| number | 数值 | 数值同时写入 `value_num` 列（REAL），便于范围查询 |
| enum | 枚举 | 必须存规范英文值（见 3.2），中文只做展示 |
| bool | 布尔 | `true` / `false` |

### 3.2 枚举字段规范值（全集）

| field_key | 允许值 |
|---|---|
| gender | `male` / `female` / `unknown` |
| abo_blood_type | `A` / `B` / `AB` / `O` / `unknown` |
| rh_blood_type | `positive` / `negative` / `unknown` |
| symptom_severity | `acute` / `chronic` / `recurrent` |
| 病症结果 result_en | `negative` / `positive` / `not_tested` |

### 3.3 多值字段（is_multi=1，共 10 个）

`high_risk_factor`、`allergy_source`、`allergy_reaction`、`accompanying_symptoms`、`positive_signs`、`negative_signs`、`followup_date`、`current_weight`、`current_temperature`、`followup_note`

- 多值字段 `seq` 从 1 连续递增；单值字段 `seq` 固定为 0；
- 唯一约束 `UNIQUE(record_id, field_key, seq)` 保证不重不漏；数据库层 `seq` 为 **NOT NULL**——SQLite 中 NULL 不参与 UNIQUE 冲突判断，必须「非空 + 唯一」组合才成立。

### 3.4 双语存储边界

只有两类字段需要真正的英文值：

1. **枚举字段** —— 规范值本身就是英文（如 `gender`=`male`）；
2. **病症词典** —— `disease_terms.term_key` 是跨系统与 DNA 载荷的稳定标识。

其余开放文本一律 `value_en = value_cn`，禁止为凑英文造不准确翻译。DNA 编码用 `json.dumps(..., ensure_ascii=True)` 将中文转为 `\uXXXX`，无损可逆、纯 ASCII。

### 3.5 字典维护规则

1. 新增字段必须走 `add_field_definition()` 登记，并在 PR 中说明来源，禁止业务代码临时造 key；
2. 字段停用置 `is_active=0`：前端不再渲染，历史值仍可读；
3. 中文标签 `label_cn` 可修改；`field_key`、`term_key` 不可改；
4. 字段字典种子数据由 `scripts/gen_field_seed.py` 从设计文档自动生成（`data/seed/seed_field_definitions.sql`，60 条，幂等可重复执行）。
