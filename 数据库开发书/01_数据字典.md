## 3. 类型与取值规范

### 3.1 value_type 类型定义

| 类型 | 含义 | 存储要求 |
|---|---|---|
| text | 开放文本 | `value_cn` 存中文；`value_en` 与 `value_cn` 相同（开放文本不做翻译） |
| date | 日期 | 统一 `YYYY-MM-DD` 格式 |
| number | 数值 | 数值同时写入 `value_num` 列（REAL），便于范围查询 |
| enum | 枚举 | 必须存规范英文值（见 3.2），中文只做展示 |
| bool | 布尔 | `true` / `false` |

### 3.2 枚举字段规范值（全集）

| field_key | 允许值 |
|---|---|
| gender | `male` / `female` / `unknown` |
| abo_blood_type | `A` / `B` / `AB` / `O` / `unknown` |
| rh_blood_type | `positive` / `negative` / `unknown` |
| symptom_severity | `acute` / `chronic` / `recurrent` |
| 病症结果 result_en | `negative` / `positive` / `not_tested` |

### 3.3 多值字段（is_multi=1，共 10 个）

`high_risk_factor`、`allergy_source`、`allergy_reaction`、`accompanying_symptoms`、`positive_signs`、`negative_signs`、`followup_date`、`current_weight`、`current_temperature`、`followup_note`

- 多值字段 `seq` 从 1 连续递增；单值字段 `seq` 固定为 0；
- 唯一约束 `UNIQUE(record_id, field_key, seq)` 保证不重不漏；数据库层 `seq` 为 **NOT NULL**——SQLite 中 NULL 不参与 UNIQUE 冲突判断，必须「非空 + 唯一」组合才成立。

### 3.4 双语存储边界

只有两类字段需要真正的英文值：

1. **枚举字段** —— 规范值本身就是英文（如 `gender`=`male`）；
2. **病症词典** —— `disease_terms.term_key` 是跨系统与 DNA 载荷的稳定标识。

其余开放文本一律 `value_en = value_cn`，禁止为凑英文造不准确翻译。DNA 编码用 `json.dumps(..., ensure_ascii=True)` 将中文转为 `\uXXXX`，无损可逆、纯 ASCII。

### 3.5 字典维护规则

1. 新增字段必须走 `add_field_definition()` 登记，并在 PR 中说明来源，禁止业务代码临时造 key；
2. 字段停用置 `is_active=0`：前端不再渲染，历史值仍可读；
3. 中文标签 `label_cn` 可修改；`field_key`、`term_key` 不可改；
4. 字段字典种子数据由 `scripts/gen_field_seed.py` 从设计文档自动生成（`data/seed/seed_field_definitions.sql`，60 条，幂等可重复执行）。

## 4. 标准诊断编码接入（v3.1）

### 4.1 三层字典的职责边界

系统里有三套「名字」，容易混，先划清：

| 层 | 表 | 条数 | 答什么问题 | 谁维护 |
|---|---|---:|---|---|
| 业务字段 | `field_definitions` | 60 | 这张表要填**哪些项** | 产品/医学顾问，改动需评审 |
| 筛查词条 | `disease_terms` | 236 | 每项要判**阴阳的病症清单** | 医学顾问，`term_key` 不可变 |
| 诊断编码 | `icd_codes` | 35,867 | 病症对应**国家标准的哪个码** | 国家卫健委，随版本整体替换 |

- **不能合并**：`disease_terms` 是「问诊项」，含 `无 / 不详 / 正常` 这类非疾病项（这 3 条在码表里没有对应码）；`icd_codes` 是「诊断全集」，两者是一对多的引用关系，不是同一份数据。
- **关联方式**：`disease_terms.icd_code` → `icd_codes.code`（可空外键），`disease_terms.icd_match` 记录绑定方式（exact / manual / ai / none）。
- **对 DNA 载荷无影响**：载荷引用的是 `term_key`，不是 `icd_code`；`payload_version` 仍为 v2，老档案无需重编码。

### 4.2 `disease_category` 字段的取值口径

原口径是自由文本（"呼吸系统""消化系统"混写）。接入码表后统一为：

| 取值 | 说明 |
|---|---|
| `chapter_code` | ICD-10 章节码 `I`–`XXII`（推荐），中文名走 `icd_codes.chapter_name` 展示 |
| `category_code` | 3 位类目码（如 `E11`），用于需要更细粒度的科室/专病统计 |

- `value_cn` 存中文名（如「内分泌、营养和代谢疾病」），`value_en` 存章节码（如 `IV`）——符合 3.4「只有枚举与编码需要英文值」的边界。
- **兼容**：v1 迁移数据里的自由文本不回溯改写，读取时按 `field_value → chapter_name` 模糊匹配展示，不做强制转换（避免把「呼吸系统」误判成 `X` 章）。

### 4.3 章节映射表

22 个章节的编码区间、中文名与各类目实测条数，见《03_数据表设计说明》§11.1。三处易错点再强调一次：

1. `D` 字母跨两章：`D00–D48` 属 II（肿瘤），`D50–D89` 属 III（血液病）；
2. `H` 字母跨两章：`H00–H59` 属 VII（眼），`H60–H95` 属 VIII（耳）；
3. `V/W/X/Y` 四个字母同属 XX（外因），不要按字母拆成四章。

### 4.4 码表版本与升级

- 版本标识：`icd_codes.version = 'CN-ICD10-2.0-2022'`，导入时整表打标；
- 换版策略：新码 `INSERT`、改名 `UPDATE name`、下线 `is_active=0`，**永不物理删除**——历史档案里出现过的码必须始终可解析；
- 与 `schema_meta` 的关系：码表版本不写进结构版本（数据版本 ≠ 结构版本），单独用 `icd_codes.version` 区分。
