## 2. 范围

**做**：把纸质档案表中**手绘定稿的 6 栏封面 + 16 个空**结构化落进 SQLite，并能导出 DNA 编码载荷（封面 6 栏存 `archive_records` 列，16 空存 `answers`）。

**不做**：
- 铭文部分（姓名/性别/民族/身份证号/常住地址/档案编号/建档日期）不进枚举体系，只存 `archive_records` 的列，用于展示与密钥派生；
- 不保留 v1/v2 的 `field_definitions`（60 字段）、`record_entries`（键值表）、`record_diseases`、`disease_terms`（236 条自造词条）——这是 v4.0 的核心决策；
- 不自造疾病分类轴：科室轴与系统轴合并，统一用 ICD 22 章；
- **最终呈现以手绘表格为准（2026-11-17 定稿）**：出生史、婚育史/月经史、输血史、预防接种史、随访记录、生命体征、阴性体征等 27 处原文条目**不入库**（呈现界面没有这些栏位）；《10.17 医疗信息框架》降为候选词条的原始出处，不再是字段清单依据。

| 14 | `chief_complaint` | 症状表现（主诉） | multi_enum | 1 | 症状表现 | ICD-10 第 XVIII 章 + 自建 |
| 15 | `accompanying_symptom` | 伴随症状 | multi_enum | 0 | 症状表现 | 复用 14 的词条，前缀 `history__` |

**类型分布**：多选 14 / 单选 2 = 16，**没有任何文本/日期/数值空**——手绘最终呈现里的每个空都能从候选项点选，这正是「能填的必须是枚举」的落地。

三条口径：
1. **2026-11-17 收窄**：最终呈现以手绘表格为准，43 处原文条目只入 16 个空（铭文 6 栏存封面表）；出生史、婚育史、随访等 27 处不入库，被砍栏位的候选词条随《10.17 医疗信息框架》保留追溯。
2. **家族史 / 伴随症状复用而非复制**：保留两份 `options` 记录（`(field_id, name_cn)` 唯一），共用同一 `icd_code`，`option_key` 加 `family__` / `history__` 前缀。
3. **疾病分类沿用合并决策**（2026-11-11）：科室轴 + 系统轴两套合并为一个 `disease_category`，选项 = ICD 22 章。

## 5. 建表

全量 DDL 见 **`04_建表脚本_v4.0.sql`**（10 表 + 21 索引 + 9 外键 + 版本写入 + 自检）。本节只给四张新表的关键约束，实现时以脚本为准。

### 5.1 `sections`
`section_key` 唯一；`parent_id` 自引用；`level ∈ {1,2,3}`；`UNIQUE(level, sort_order)` 由索引承担。

### 5.2 `fields`
- `field_key` 唯一，**入库后不可改名**（DNA 载荷按 key 序列化）；
- `value_type ∈ {multi_enum, enum, text, date, number, number_group}`；
- `is_required`：0 = 可不填；`derive_from`：非空表示由另一空派生；
- `UNIQUE(section_id, sort_order)` 保证文档顺序不串位。

### 5.3 `options`
- `option_key` 全局唯一，规则见 §6；
- `UNIQUE(field_id, name_cn)`：同一空下不重名，跨空可重名；
- `icd_code` 可空、**不唯一**（一个码可对应多个业务项），`REFERENCES icd_codes(code)`；
- `source ∈ {icd, icd9, wst, custom, derived}`（`icd9` = 手术操作分类代码国家临床版 3.0；`wst` = WS/T 364.5 值域）；
- **不存 ICD 名称**，一律 JOIN `icd_codes`，避免一处改名两处不一致。

### 5.4 `answers`
- 枚举型：`option_id` 非空、三个值列必须全空；
- 值型：`option_id` 为空、对应值列非空；
- 两者由 `CHECK` 强制，跨表判断 `value_type` 由应用层负责（SQLite 做不到）；
- `seq` 用于一对多（多次随访 / 多值）；
- 唯一索引 `uq_answers_enum`（partial）：同一档案 + 同一空 + 同一序号下，同一枚举项只能出现一次。

## 6. 枚举项（options）命名规则

| 情况 | 规则 | 例 |
|---|---|---|
| 有 ICD-10 码 | `icd_` + 码规范化（小写、`.`→`_`、`+`→`_plus`、`*`→`_star`） | E11.900 → `icd_e11_900`；B06.801+J17.1 → `icd_b06_801_plus_j17_1` |
| 有手术码（ICD-9-CM3） | `icd9_` + 码规范化，`source='icd9'` | 阑尾切除 47.0900 → `icd9_47_0900` |
| WS/T 值域代码 | `wst_` + 表号 + 值，`source='wst'` | 吸烟状态值 1 → `wst_cv02_10_101_1` |
| 语义明确、无合适码 | 英文短名 snake_case | 高血压 → `hypertension` |
| 复用项加前缀 | `family__` / `history__` / `neg__` | `family__hypertension` |
| 章节派生 | `chapter_` + 罗马数字小写 | `chapter_iv`（内分泌营养代谢） |

`name_en` 允许暂空（`DEFAULT ''`），由 S4 批量生成 → S5 人工复核后写 `reviewed_by`。

## 7. 核心读写 SQL

### 7.1 渲染表单（未填的空也要显示）

```sql
SELECT s.sort_order, s.name_cn AS 表头, f.sort_order, f.field_key, f.name_cn AS 空,
       f.value_type, f.is_required,
       COUNT(a.id) AS 已填条数
FROM fields f
JOIN sections s ON s.id = f.section_id
LEFT JOIN answers a ON a.field_id = f.id AND a.record_id = :record_id
WHERE s.section_key <> 'inscription'
GROUP BY f.id
ORDER BY s.sort_order, f.sort_order;
```

### 7.2 保存一个多选项（幂等）

```sql
INSERT INTO answers (record_id, field_id, option_id, seq, updated_at)
SELECT :record_id, f.id, o.id, 0, datetime('now')
FROM fields f
JOIN options o ON o.field_id = f.id
WHERE f.field_key = :field_key AND o.name_cn = :name_cn
  AND NOT EXISTS (
    SELECT 1 FROM answers a
    WHERE a.record_id = :record_id AND a.field_id = f.id
      AND a.option_id = o.id AND a.seq = 0
  );
```

### 7.3 保存一个值型空

```sql
INSERT INTO answers (record_id, field_id, value_num, seq, updated_at)
VALUES (:record_id, (SELECT id FROM fields WHERE field_key = :field_key), :value, 0, datetime('now'))
ON CONFLICT DO NOTHING;
```

> 值型空的覆盖写用「先删后插」或 `UPDATE ... WHERE record_id=? AND field_id=? AND seq=?`，不要依赖 UPSERT（`option_id` 为 NULL 时唯一性不成立）。

### 7.4 加载整份档案

```sql
SELECT s.name_cn AS 表头, f.name_cn AS 空, f.value_type,
       COALESCE(o.name_cn, a.value_text) AS 显示值,
       a.value_num, a.value_date, a.seq
FROM answers a
JOIN fields f   ON f.id = a.field_id
JOIN sections s ON s.id = f.section_id
LEFT JOIN options o ON o.id = a.option_id
WHERE a.record_id = :record_id
ORDER BY s.sort_order, f.sort_order, a.seq, o.sort_order;
```

### 7.5 导出 DNA 载荷（按 section 顺序序列化）

```sql
SELECT s.section_key, f.field_key, o.option_key, a.value_text, a.value_num, a.value_date
FROM answers a
JOIN fields f   ON f.id = a.field_id
JOIN sections s ON s.id = f.section_id
LEFT JOIN options o ON o.id = a.option_id
WHERE a.record_id = :record_id
ORDER BY s.sort_order, f.sort_order, a.seq, COALESCE(o.sort_order, 0);
```

序列化规则：`section_key.field_key = option_key`，多值按 `seq` 拼数组；空值不出现（保证同一份档案的载荷稳定）。

## 9. 安全边界

1. **铭文不入库枚举**：姓名/身份证号等只存 `archive_records`，不产生 `options`，不参与下拉。
2. **码表只读**：`icd_codes` 无业务写入路径。
3. **答案不可跨档案复用**：`answers.record_id` 外键到 `archive_records`，删除档案级联清答案。
4. **DNA 链不可断**：`dna_sequences.record_id` 外键**不设 CASCADE**，物理删除档案会被拒绝。
5. **无账号体系（v4.1）**：单机单用户，`users` 表已删；操作留痕靠 `user_activity_log`（审计用，不是权限控制）。
