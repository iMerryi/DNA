# v4.0 数据库重塑设计

> ⚠️ **状态（2026-11-17 更新）：本文描述的是 v4.0 / 42 空时期的设计论证。**
> 最终呈现已收窄为手绘表格（8 表头 / 16 空全枚举），生产结构版本为 **v4.1（10 表无账号）**。
> 现行口径见 `00_数据库开发书_最终版_v4.0.md`（内容 v4.1）；本文仅回答"为什么当初这么改"，其中 42 空、users 表等描述均已过时，勿据此施工。

> 定位：**推倒重设计，不是在 v3.1 上打补丁。**
> 依据：《10.17 医疗信息框架》的 14 个表头 + 43 处空（合并两处分类后入库 42 条）；《疾病分类与代码国家临床版 2.0（2022 汇总版）》35,867 条码。
> 状态：设计稿，待评审。本文只定结构，不含实现代码。

## 1. 为什么必须重塑

v3.0 → v3.1 那次改动把 ICD 码表**挂**在了旧模型旁边，但旧模型的骨架没动。结果是四组无法调和的冲突：

| # | 冲突 | 具体表现 |
|---|---|---|
| 1 | 两套分类并存 | `disease_terms` 自造 8 类（五官科/儿科/内科/外科/妇科/皮肤科/过敏与免疫/通用）；`icd_codes` 国家 22 章 + 2,046 类目。同一个「疾病分类」有两套互不兼容的答案 |
| 2 | 语义层级错位 | `disease_terms` 是**筛查项**（判阴阳），ICD 是**诊断编码**（下诊断）。二者不是同一层东西，用外键硬绑只会让「阳性了，诊断是什么」无法回答 |
| 3 | 字段口径混杂 | `disease_category` 既要存章节码 `IV`、又要存自由文本「呼吸系统」、还要兼容 v1 迁移值，三种语义挤在一个字段，任何 CHECK 都写不下去 |
| 4 | 字典散成三份 | 60 个字段字典、236 条词条、35,867 条码表各自为政，关联全靠可空外键，没有任何完整性约束能兜住 |

根本原因：**v3.x 描述的是「一张筛查表」，而国家码表描述的是「诊断全集」。** 要接国家码表，就得换描述方式。

---

## 2. 重塑原则

1. **表头即骨架**：数据库结构由文档的表头决定，不由历史代码决定。14 个表头原样落库。
2. **空即字段，字段必可枚举**：存储部分下每一处「空」都在库里有一条记录；能枚举的挂枚举项，不能枚举的标明值型。
3. **中文名为一等公民**：系统的选项以中文疾病/项目名为入口，ICD 码是它的权威来源，不是相反。
4. **英文键自建**：ICD 不提供英文名，`option_key` 由我们生成 + 人工审核，规则统一、可校验、可回溯。
5. **铭文部分不建枚举库**：铭文仅作表头占位（`sections` 保留一条），其下不产生 `fields` 与 `options`；姓名、性别、出生日期等只用于 DNA 密钥派生，不进枚举体系。

---

## 3. 新模型总览

```
sections            表头（14 条，三级：2 个 H1 + 3 个大类 + 9 个小标题）
  └─ fields         空（42 条，文档 43 处「· xxx：」中两处分类合并为一）
       └─ options   枚举项（系统下拉/多选的唯一来源，内容主要来自 ICD）
                        │
                        └── icd_codes（35,867 条，只读来源与校验锚点）

archive_records     档案（铭文信息，仅存姓名等密钥派生所需字段）
  └─ answers        档案填写结果（引 field_id + option_id / 值）
```

保留不动：`dna_sequences`、`decode_records`、`user_activity_log`、`schema_meta`。`users` 账号表于 v4.1 评估后移除：单机单用户下账号不提供真实安全（能物理接触电脑的人可直接打开 db 文件），不参与"数据不出机 + DNA 编码 + 密钥哈希不落库"的真实防线，只增加每次启动的登录摩擦；**操作日志保留**（去掉 user_id 列）。

废弃：`field_definitions`（60 条）、`record_entries`（键值表）、`record_diseases`（筛查结果表）、`disease_terms`（236 条自造词条）。

## 4. 表结构

### 表1　`sections` 表头

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| section_key | TEXT | NOT NULL UNIQUE | 英文键，如 `past_and_family_history` |
| name_cn | TEXT | NOT NULL | 表头原文，如「1.既往史/家族史：」 |

| level | INTEGER | CHECK 1/2/3 | 1 = H1（铭文/存储），2 = H2（一、二、三），3 = H3（九个小标题） |

| 2 | 1 | — | `storage` | 存储部分： |
| 3 | 2 | storage | `patient_background` | 一、患者基础与背景信息类（不可或缺） |

| 7 | 3 | patient_background | `reproductive_history` | 4.婚育史/月经史： |
| 8 | 3 | patient_background | `birth_and_family` | 5.出生史与家庭信息： |

| 11 | 3 | clinical_history | `symptoms` | 2.症状表现： |

> `inscription` 下不产生任何 `fields`；`storage` 是挂载点，其子孙节点下才挂 42 个空。

### 表2　`fields` 空定义

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| field_key | TEXT | NOT NULL UNIQUE | 英文键，如 `past_medical_history` |
| name_cn | TEXT | NOT NULL | 空名，如「既往患病史」 |
| name_en | TEXT | NOT NULL | 英文名 |
| section_id | INTEGER | NOT NULL，FK → sections.id | 归属小标题 |
| value_type | TEXT | CHECK 值域 | `multi_enum` / `enum` / `text` / `date` / `number` / `number_group` |
| is_multi | INTEGER | CHECK 0/1 | 与 `value_type` 冗余但便于前端直接判断 |
| is_required | INTEGER | CHECK 0/1，默认 1 | 0 = 可不填（如阴性体征「无异常即留空」、婚育史对男性） |
| derive_from | TEXT | 默认 '' | 非空时表示由另一空派生，值为其 `field_key`（如 `negative_signs ← positive_signs`） |
| unit_cn / unit_en | TEXT | DEFAULT '' | 数值型单位，如 ℃ / °C |
| sort_order | INTEGER | NOT NULL | 空在小标题内的顺序 |
| note | TEXT | DEFAULT '' | 括号说明原文（如「不仅是高危因素…」） |

`value_type` 取值口径：

| 值 | 含义 | 前端控件 | 是否有 options |
|---|---|---|---|
| `multi_enum` | 多选枚举 | 多选标签/复选 | 有 |
| `enum` | 单选枚举 | 下拉/单选 | 有 |
| `text` | 自由文本 | 输入框 | 无 |
| `date` | 日期 | 日期控件 | 无 |
| `number` | 单个数值 | 数字框 | 无 |
| `number_group` | 一组指标（如生命体征 4 项） | 多指标输入 | 无（指标名进 `note` 或独立子表） |

### 表3　`options` 枚举项（核心表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| option_key | TEXT | NOT NULL UNIQUE | 英文键，自建，见 §6 |
| name_cn | TEXT | NOT NULL | 中文名，如「2型糖尿病」 |
| name_en | TEXT | NOT NULL | 英文名（AI 生成 + 人工审） |
| field_id | INTEGER | NOT NULL，FK → fields.id | 挂在哪个空下 |
| icd_code | TEXT | 可 NULL，FK → icd_codes.code | 权威来源码 |
| source | TEXT | CHECK 值域 | `icd`（来自码表）/ `custom`（自建，如「无」「不详」）/ `derived`（由码表加工，如章节分类项） |
| is_active | INTEGER | CHECK 0/1 | 启停 |
| sort_order | INTEGER | DEFAULT 0 | 展示顺序 |
| reviewed_by | TEXT | DEFAULT '' | 人工复核人 |
| reviewed_at | TEXT | DEFAULT '' | 复核时间 |

关键约束：

- **`(field_id, name_cn)` 唯一**：同一个空下不允许重名项（跨空可以重名，如「贫血」既可作既往史也可作家族史）。
- **`icd_code` 可空但不做唯一**：一个 ICD 码可对应多个业务项（如「生长发育迟缓」与「小儿生长发育迟缓」指向同一码），也允许 `NULL`（自建项）。
- **不存 ICD 名称**：名称一律 JOIN `icd_codes`，避免「一处改名、两处不一致」。

### 表4　`icd_codes` 码表（沿用 v3.1 设计，不改）

35,867 条，`code` 主键，含 `chapter_code` / `chapter_name` / `category_code` / `is_extension` / `is_combination` / `version` / `is_active`。只读，唯一写入口是导入脚本。

### 表5　`answers` 档案填写结果

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| record_id | TEXT | NOT NULL，FK → archive_records.record_id，CASCADE | |
| field_id | INTEGER | NOT NULL，FK → fields.id | 哪个空 |
| option_id | INTEGER | 可 NULL，FK → options.id | 选中的枚举项（枚举型必填） |
| value_text | TEXT | DEFAULT '' | 文本值（`text` 型） |
| value_num | REAL | 可 NULL | 数值（`number` 型） |
| value_date | TEXT | DEFAULT '' | 日期（`date` 型） |
| seq | INTEGER | NOT NULL，DEFAULT 0 | 多值/多次随访序号 |
| updated_at | TEXT | NOT NULL | |

约束：`CHECK` 限定「枚举型必须 `option_id` 非空、值型必须 `option_id` 为空」，由应用层与触发器共同保证（SQLite 的 CHECK 无法跨表判断 `value_type`，故此处只做单行自洽校验）。

三处口径调整——**已确认（2026-11-11）**：

1. **24/25 合并为一个空**（已采纳）：现文档「按病症词典分类」8 项与「按系统分类」10 项是两套并行分类，接 ICD 后只剩一套——章节分类。库中只留 `disease_category` 一个空，选项为 22 章（`derived`）。**`fields` 由 43 条降为 42 条**，文档正文两行不动（文档是采集口径说明，库是执行口径）。

3. **6/30 复用而非复制**（已采纳）：家族史复用既往史的疾病项、伴随症状复用主诉的症状项，但**不能共用同一批 `options` 记录**（`(field_id, name_cn)` 唯一）。做法是保留两份 `options` 记录、共用同一个 `icd_code`，由 `option_key` 前缀区分（如 `family__hypertension` / `history__hypertension`）。

## 6. 英文键规划

ICD 国家临床版只给中文名，英文键必须自建。三类键、三套规则：

### 6.1 键的三种类型

| 类型 | 数量级 | 规则 | 示例 |
|---|---|---|---|
| `section_key` | 14 | 语义短名，snake_case | `past_and_family_history` |
| `field_key` | 42 | 语义短名，snake_case | `past_medical_history` |
| `option_key` | 236 + ICD 相关项 | **分层**，见下 | `icd_e11_900` / `hypertension` |

### 6.2 `option_key` 的分层策略

| 子类 | 规则 | 示例 | 数量估算 |
|---|---|---|---|
| 有 ICD 码的项 | `icd_` + 码规范化（小写、`.`→`_`、`+`/`*`→`_plus`/`_star`） | E11.900 → `icd_e11_900`；B06.801+J17.1 → `icd_b06_801_plus_j17_1` | ~1 万 |
| 自建项（无 / 不详 / 正常 / 生活方式） | 语义英译，短小、可读 | `none` / `unknown` / `normal` / `former_smoker` | ~300 |
| 派生项（章节、阴性体征） | 父键 + 后缀 | `chapter_iv` / `neg__rash` | ~200 |

**为什么有码的项不直接翻英文名**：35,867 条全量翻译既慢又容易重名（「贫血」类名称在码表里重复出现），而码本身已是国际唯一标识，派生键天然唯一、稳定、可回溯。人工只需为高频项（预计 300–500 条）补语义键，其余用码派生键兜底。

### 6.3 英文名（`name_en`）与英文键是两件事

- `name_en`：给人看的展示名，需真实翻译（`Type 2 diabetes mellitus`）。
- `option_key`：给机器用的稳定标识，一经生成不改。

**AI 填充流程**（下一步执行，本文只定规则）：

1. 导出待填清单（`field_id` + `name_cn` + `icd_code`）为 CSV；
2. AI 按 `name_en` 逐条生成译文，按 §6.2 生成 `option_key`；
3. 规则校验脚本：键格式、唯一性、长度 ≤ 48、禁止中文与空格；
4. 人工审核：重点看三类——一名多码（贫血、关节炎）、同义重复（生长发育迟缓 / 小儿生长发育迟缓）、翻译偏差（中医病名、罕见病）；
5. 复核结果写回 `reviewed_by` / `reviewed_at`，未复核项前端标注「待审」。

## 7. ICD 码表接入策略

| 决策点 | 结论 | 理由 |
|---|---|---|
| 入库范围 | **全量 35,867 条入 `icd_codes`**；`options` 只挂与业务相关的子集 | 码表是权威底座，全量才能保证历史档案里的码永远可解析；`options` 是业务视图，按需挂载 |
| 章节筛选 | 在 `options` 层控制，不在码表层裁剪 | 码表裁剪后无法追溯「为什么这个码不在」 |
| 版本升级 | 整表换版：新增 INSERT、改名 UPDATE、下线 `is_active=0` | 永不物理删除 |
| 疾病分类口径 | 22 章（`chapter_code`），来自 `icd_codes` | 取代自造的 8 类 |

`options` 优先挂载的章节（建议起点，实测合计 **16,140 条**）：

| 章节 | 名称 | 条数 | 与业务关系 |
|---|---|---:|---|
| IV | 内分泌、营养和代谢疾病 | 1,927 | 高（PKU、甲减、糖尿病） |
| VI | 神经系统疾病 | 1,376 | 高（脑瘫、癫痫） |
| X | 呼吸系统疾病 | 944 | 高（哮喘、肺炎） |
| XI | 消化系统疾病 | 2,329 | 高（腹泻、胃炎） |
| XII | 皮肤和皮下组织疾病 | 1,119 | 高（湿疹、荨麻疹） |
| XIV | 泌尿生殖系统疾病 | 1,472 | 中 |
| XVII | 先天性畸形、变形和染色体异常 | 2,008 | 高（出生缺陷筛查） |
| XVIII | 症状、体征和临床与实验室异常所见 | 877 | 高（主诉与体征来源） |
| I | 某些传染病和寄生虫病 | 2,473 | 中（结核、肝炎） |
| XXI | 影响健康状态和与保健机构接触的因素 | 1,615 | 中（Z88 过敏状态） |
